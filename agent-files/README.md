# 取消報修功能：AI 開發 Agent 文件

這個資料夾把第 C 組 HW1「取消報修功能」的軟體規格書，整理成一組 AI 開發 Agent 可以閱讀、理解並依循的文件。

## 文件結構

```text
agent-files/
├─ README.md
├─ software-spec.md
├─ AGENTS.md
└─ skills/
   └─ status-change-review/
      └─ SKILL.md
```

## 三個核心文件

| 檔案 | 內容 | 回答的問題 |
|---|---|---|
| `software-spec.md` | 系統目標、使用者、案件狀態、功能、API、限制與完成條件 | 系統要做什麼？做到什麼程度算完成？ |
| `AGENTS.md` | Agent 的角色、修改前的分析步驟、開發規則與回報格式 | Agent 應該怎麼修改這個專案？ |
| `skills/status-change-review/SKILL.md` | 檢查案件狀態變更的步驟、測試情境與輸出格式 | 遇到狀態變更類任務，要按什麼步驟檢查？ |

## 為什麼這樣分？

實作取消報修時，最容易出錯的地方都跟「狀態」有關：已在處理的案件不應該被取消、後台選單不認得「已取消」、只在前端隱藏按鈕卻沒有後端檢查。因此：

- 規格書把狀態轉換規則寫成表格，讓 Agent 有明確依據。
- 工作規則要求 Agent 沿著資料流同時檢查前台、後台與後端。
- Skill 把狀態變更的檢查方法固定下來，之後新增「退回案件」等功能時也能重複使用。

## 如何使用

1. 將專案根目錄（含 `app.py`）與本資料夾一起開啟，建立新的 AI 開發對話。
2. 請 Agent 先閱讀 `agent-files/AGENTS.md`，它會依規則讀取 `software-spec.md`。
3. 任務涉及案件狀態時，請 Agent 依照 `skills/status-change-review/SKILL.md` 檢查。

可用下列提示測試：

```text
請依照 agent-files/AGENTS.md 的規則，協助我規劃「管理者退回案件」功能。
先不要修改檔案，請說明受影響的檔案、狀態轉換規則、測試案例，以及需要我確認的地方。
```

觀察 Agent 是否會先讀規格書、對照狀態表、同時檢查前後台，並把不確定的部分列為「需要人工確認」。

不同 AI 工具可能要求不同的檔名或資料夾位置，使用前請依所選工具的文件格式調整。
